# 🎯 Стратегический роадмап — opencode-windows-scheduler

> Цель: **стать лучшим планировщиком/оркестратором для OpenCode, оставаясь бесплатным и open source.**
> Основано на аудите плагина (ноябрь 2026). Тактический спринт-план — в [ROADMAP.md](./ROADMAP.md).

---

## Позиционирование

**Мы не «cron для OpenCode». Мы — локальная платформа оркестрации AI-задач:**
расписание + зависимости (DAG) + матрицы (fan-out) + политики качества + наблюдаемость.

| Принцип | Что это значит на практике |
|---|---|
| **Бесплатно навсегда** | MIT, без SaaS, без телеметрии, без «pro»-функций за деньги |
| **Локально по умолчанию** | Данные, история и логи — на машине пользователя, без облака |
| **Open source-first** | Публичный roadmap, good-first-issues, CI на 3 ОС, англоязычная документация |
| **Оркестрация, а не таймер** | Ров — DAG, матрицы, политики, дашборд. Cron — commodity, его скопируют |

**Текущая точка:** функционально сильнее всех в экосистеме, но:
- нет LICENSE / npm / CI / английского README → нас не находят;
- агент видит 4 инструмента из ~30 RPC-методов (~35–40% функционала);
- нет table stakes: one-shot, session continuity, guard, worktree, декларативные job-файлы, TUI.

## Горизонт 1–2 месяца: закрыть table stakes

> Базовые сценарии, которые ожидают от планировщика. Без них мы «мощнее, но неудобнее».

### 1.1 One-shot расписание (3–4 дня)
- `runAt` (ISO-дата) / `delaySeconds` в `schedule_task`, RPC, GUI, dashboard.
- OS-бэкенды: ONCE (Windows/macOS), `at`/systemd-timer с `OnCalendar` (Linux).
- Статус в истории: `scheduled → running → success/error`.

### 1.2 Session continuity (4–5 дней)
- Режимы `session: "new" | "reuse" | "last"`; хранение `sessionId` у задачи.
- Наследование `agent`/`model` из сессии (как у pan17), опционально.
- Очистка/компакция сессии по политике.

### 1.3 Guard-условия (2–3 дня)
- `guard?: string` — shell-команда; ненулевой код = пропуск запуска.
- Статус `skipped` с причиной в истории; не влияет на DAG-зависимых.
- Примеры: «только если есть изменения», «только если CI зелёный».

### 1.4 Worktree-изоляция (3–4 дня)
- `worktree: true` — одноразовый `git worktree` на запуск, базовый ref настраивается.
- Политика очистки (успех/ошибка/через N дней), защита от незакоммиченных изменений.
- Отображение в истории: путь worktree, ветка/ref.

### 1.5 Декларативные job-файлы (5–6 дней)
- Source of truth: `.opencode/scheduler/*.json` (или `.yaml` без новых зависимостей — JSON).
- Синхронизация при активации плагина + file-watcher; конфликты — в лог/историю.
- `export`/`init` в репозиторий; git-committable, ревью через PR.

### 1.6 TUI-центр задач (5–6 дней)
- Список задач со статусами, группировка матриц, run/pause/resume, хвост логов.
- `src/tui.tsx` читает реальные задачи и историю, группирует клоны матриц под родителем, поддерживает run/pause/resume (клик по задаче или `Ctrl+Shift+J`, плюс палитра команд), показывает последние 40 строк лога и навигацию по списку (`Ctrl+Shift+↑/↓`, `Ctrl+Shift+Enter`).

### 1.7 Per-task permissions (4–5 дней)
- Модель `action / resource / effect` либо строгая реализация текущих `allowedTools`/`deniedTools`.
- Реальное применение на уровне исполнения, аудит-лог решений.

**Готово, когда:** базовые сценарии (one-shot, reuse session, guard, worktree, md/json в репо, TUI) закрыты; `npm test` и CI зелёные; документация обновлена.

## Горизонт 3–6 месяцев: ров, который не скопируют за неделю

### 2.1 Позиционирование «CI/CD для AI-агентов»
- Лендинг в README: 10 рецептов (утренний дайджест, matrix по репо, деплой-пайплайн, авто-фикс CI, ночная аналитика).
- Статья/доклад: «почему cron недостаточно для агентов» (DAG, политики, наблюдаемость).
- Benchmarks: накладные расходы, надёжность на 3 ОС.

### 2.2 Адаптер к нативной службе расписаний OpenCode (2.2.3+)
- Не воевать с хостом: использовать нативный scheduler как транспорт, себе оставить оркестрацию.
- Feature-flag `nativeScheduler: auto|on|off`; миграция существующих задач.
- Убрать из README рекомендацию «отключите `experimental.schedules`» — заменить на «работаем вместе».

### 2.3 Политики, approvals и бюджеты
- Approval-gates для опасных действий (деплой, удаление, внешние вызовы).
- Бюджеты: токены/стоимость на задачу и матрицу, авто-пауза при превышении.
- Квоты на параллелизм (глобально и на проект), приоритеты очереди.

### 2.4 Мультипроектность и секреты
- Профили (`default`, `work`, …) с отдельными БД/настройками/портами.
- Env-переменные на workspace, маскировка секретов в логах и истории.
- Экспорт/импорт с шифрованием секретов (опционально, без внешних зависимостей — WebCrypto).

### 2.5 Интеграции и наблюдаемость
- Входящий webhook-триггер `POST /api/hooks/:task` с HMAC — запуск из GitHub Actions/GitLab CI.
- Prometheus `/metrics`, JSONL-логи, экспорт истории в OpenTelemetry.
- Плагин-хуки: `beforeRun`/`afterRun` для расширений сообщества.

### 2.6 Сообщество и устойчивость
- `good-first-issue`, discussions, «awesome-recipes», шаблоны задач.
- Semver, changelog, процесс релизов, ответ на issues ≤ 72 ч.
- Русская и английская документация синхронно.
