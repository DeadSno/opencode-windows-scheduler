# 🎯 Стратегический роадмап — opencode-windows-scheduler

> Цель: **стать лучшим планировщиком и оркестратором для OpenCode, оставаясь бесплатным и open source.**
> Тактический спринт-план — в [ROADMAP.md](./ROADMAP.md), выпущенные изменения — в [CHANGELOG.md](./CHANGELOG.md).

---

## Позиционирование

**Мы не «cron для OpenCode». Мы — локальная платформа оркестрации AI-задач:**
расписание + зависимости (DAG) + матрицы (fan-out) + политики качества + наблюдаемость.

| Принцип | Что это значит на практике |
|---|---|
| **Бесплатно навсегда** | MIT, без SaaS, без телеметрии, без «pro»-функций |
| **Локально по умолчанию** | Данные, история и логи — на машине пользователя |
| **Open source-first** | Публичный roadmap, CI на 3 ОС, английская документация |
| **Оркестрация, а не таймер** | Ров — DAG, матрицы, Quality Gates, наблюдаемость. Cron скопируют за неделю |

**Текущая точка (1.4.0):**

- опубликован в npm, CI зелёный на Windows / macOS / Linux;
- 24 инструмента агента — паритет с RPC-поверхностью;
- one-shot запуски, непрерывность сессий, профили, webhooks, Telegram и нативные toast, тихие часы, Prometheus и OTLP — есть;
- зашифрованные секреты (${secret:NAME}) и журнал аудита — есть;
- английский README и `docs/` — основные, русский синхронизирован в `docs/README.ru.md`.

**Чего ещё нет:** git-триггеров, pipeline-as-code, Docker-runner, approvals и remote runners.

## Горизонт 0–1 месяц: ежедневные сценарии и доверие

### 1. Уведомления, которые доходят (P1)

Telegram Bot API и нативные уведомления ОС, фильтры по статусам и задачам, тихие часы. Webhook уже есть, но им пользуется меньшинство.

**Почему:** соседний `@mohak34/opencode-notifier` набирает ~12k загрузок в месяц только на desktop-уведомлениях — спрос доказан.

### 2. Секреты и аудит (P1) — Released in 1.4.0

Зашифрованное хранилище (${secret:NAME}), маскирование в логах и экспорте, audit log всех мутаций задач, инструменты manage_secrets / get_audit_log.

**Почему:** без этого «CI/CD для агентов» не продаётся даже бесплатно — в задачах живут токены и доступы.

### 3. Git-триггеры и условия (P2)

Новые коммиты в ветке, фильтр по путям, glob-маски, временные окна. Сейчас `watchPath` — один файл или папка.

## Горизонт 2–4 месяца: CI/CD-оркестрация

### 4. Pipeline-as-code (P2)

`opencode.pipeline.yaml` в репозитории + CLI `opencode pipeline validate|run|export`. DAG, матрицы и Quality Gates описываются файлом, который можно ревьюить в PR.

**Почему:** это водораздел между «планировщиком» и «оркестратором». Ни один плагин экосистемы пока не умеет pipeline-as-code.

### 5. Runner abstraction и Docker (P2)

Локальный процесс, Docker, SSH-хост. Задача описывает *что* делать, runner — *где*. Изоляцию не изобретаем: Docker / Landstrip.

### 6. Approvals, окружения, артефакты (P3)

Ручное подтверждение перед деплоем, dev / staging / prod, отчёты и coverage как артефакты запуска.

### 7. Remote runners (P3)

Агент на удалённой машине, центральный дашборд, очередь и конкурентность на кластере. Делать после подтверждения спроса.

## Ров, который не скопируют за неделю

1. **Windows-супервизия.** Конкурент `opencode-scheduler` прямо предупреждает, что на Windows не гарантирует no-overlap и таймауты; у нас обёртки, lock-файлы, crash recovery и единая модель на трёх ОС.
2. **OpenCode v2.** Часть плагинов всё ещё на устаревшем конфиге `plugin` и не подтверждает совместимость с v2.
3. **Оркестрация.** DAG, матрицы, Quality Gates, `partial`-статусы, dry-run и история — этого нет ни у одного планировщика экосистемы.
4. **Локальность.** Никаких облаков и аккаунтов — конкуренты с SaaS-моделью сюда не пойдут.

**Чего не делаем:** свой sandbox, свою CI-платформу, хостинг агентов, платные тарифы.

## Риски и триггеры пересмотра

| Риск | Триггер | Ответ |
|---|---|---|
| Нативный scheduler OpenCode поглощает cron | Стабильный API расписаний | Режим `nativeScheduler`, акцент на DAG / матрицы / политики |
| Похожий плагин с GUI и CI/CD | Релиз конкурента | Ускорить pipeline-as-code и Docker runner |
| Bus factor = 1 | >5 issues без ответа | Сузить scope, заморозить P3, искать мейнтейнеров |
| API OpenCode v2 меняется | Breaking change в `@opencode/plugin` | Держать адаптер, следить за релизами, CI ловит первым |
| Расползание scope | Спринт длиннее 2 недель | Резать на вертикальные срезы, P3 — в бэклог |
