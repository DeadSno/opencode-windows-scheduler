## Ближайшие спринты

Порядок отражает приоритет: сначала то, что мешает пользователям каждый день, затем переход к CI/CD-оркестрации.

### Спринт 26 — Секреты и аудит (P1)

- Secrets management: Windows Credential Manager / macOS Keychain / Linux Secret Service (keytar) или внешний Vault; подстановка в env задачи, маскирование в логах, истории и экспорте.
- Audit log: кто создал / изменил / запустил / удалил задачу, когда и через какой интерфейс (агент, GUI, HTTP); поверх structured-log, с ротацией.
- **Готово, когда:** секреты не хранятся в открытом виде, экспорт их не раскрывает, аудит покрывает все мутации задач и проверен тестом.

### Спринт 27 — Git-триггеры и условия запуска (P2)

- Git-триггер: запуск только при новых коммитах (`HEAD` против последнего запуска), фильтр по ветке и путям (`git diff --name-only`).
- Glob-маски и ignore-списки для файловых триггеров (сейчас `watchPath` — конкретный файл или папка).
- Временные окна: «только 09:00–19:00 по будням» и поведение вне окна (skip / перенести / выполнить).
- **Готово, когда:** триггеры настраиваются через `schedule_task` и GUI, dry-run показывает причину пропуска, есть тест на git- и glob-сценарии.

### Спринт 28 — Pipeline-as-code (P2)

- `opencode.pipeline.yaml` в репозитории: versioned, reviewable, без новых зависимостей (парсер YAML — или JSON-совместимый подформат).
- CLI `opencode pipeline validate|run|export`: проверка, запуск, экспорт в JSON задач плагина.
- Импорт/экспорт пайплайна, конфликты с задачами из GUI — в лог и историю.
- **Готово, когда:** пайплайн из репозитория запускается одной командой, DAG и матрицы описываются в файле, спецификация покрыта тестом и документацией.

### Спринт 29 — Docker runner (P2)

- Runner abstraction: локальный процесс (сейчас), Docker, SSH-хост. Задача описывает *что* делать, runner — *где*.
- Docker: образ, монтирование workspace, лимиты CPU/RAM, сеть on/off; по умолчанию выключен.
- Интеграция, а не собственный sandbox: Docker / Landstrip вместо изобретения изоляции.
- **Готово, когда:** задача выполняется в контейнере с теми же хуками, Quality Gate, историей и метриками, что и локально.

### Спринт 30 — Метрики v2 (P3)

- Token efficiency score: успешные запуски на потраченные токены, отдельно успех и ошибки, по задачам и моделям.
- Cost forecasting: скользящее среднее, тренд, бюджет на день/неделю с алертом.
- Готовый Grafana dashboard JSON + инструкция (Prometheus и OTLP уже есть).

### Спринт 31 — Локализация документации (P3)

- `docs/README.zh.md` и `docs/README.es.md`, синхронизированные с английским.
- Переводы обновляются вместе с релизом; PR-шаблон для сообщества.

## Идеи без спринта

- **Guard-условия**: shell-команда, ненулевой код = пропуск запуска, статус `skipped` в истории.
- **Worktree-изоляция**: одноразовый `git worktree` на запуск, политика очистки, защита незакоммиченных изменений.
- **Approvals и окружения**: ручное подтверждение перед деплоем, dev / staging / prod, артефакты запусков.
- **Remote runners**: агент на удалённой машине, центральный дашборд, очередь и конкурентность на кластере.
- **Экспорт в CI**: адаптеры GitHub Actions и GitLab CI из pipeline-as-code (не наоборот).
- **Библиотека рецептов**: встроенные шаблоны (`nightly-refactor`, `dependency-audit`, `doc-sync`, `coverage-report`) + `manage_templates action=install`.
- **DAG в GUI**: клик по узлу → карточка задачи, zoom/pan, подсветка пути, дорожка матричных клонов.
- **Per-task permissions**: строгая реализация `allowedTools` / `deniedTools` (сейчас они advisory — см. `docs/FEATURES.md`).
- **Нативный scheduler OpenCode**: режим `nativeScheduler: auto|on|off` вместо рекомендации отключать `experimental.schedules`.
- **Имя и позиционирование**: алиас `opencode-pipeline` для 2.0, чтобы название не ограничивало кроссплатформенность.

## Правила разработки

- Node.js 20+ (`engines`), CI — Node 24 на Windows, macOS и Linux.
- Обязательны `npm run build` и `npm run build:gui`; `npm test` включает 26 сюит, включая `test-docs.mjs`.
- Новые runtime-зависимости — только с обоснованием; предпочтение optional dependencies и нативным командам ОС.
- Обратная совместимость: старые `tasks.json` и экспорт читаются без миграции пользователем.
- Каждый релиз обновляет CHANGELOG, README (EN + RU) и `docs/`; устаревшие отчёты спринтов не хранятся в корне — история живёт здесь и в CHANGELOG.
