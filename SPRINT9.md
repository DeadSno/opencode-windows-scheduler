# Спринт 9 — Модель LLM, приоритеты и история

Добавлены выбор модели, приоритет запуска и отображение модели в истории.
Изменения работают на Windows, Linux и macOS: модель передаётся в обе обёртки,
приоритет учитывается при catch-up и запуске DAG-зависимостей.

## 1. Модель LLM

- `TaskDefinition.model?: string` (`src/task-transfer.ts`) — формат OpenCode:
  `anthropic/claude-3-5-sonnet`, `openai/gpt-4o`, `deepseek/deepseek-coder`.
- Экспорт/импорт задач сохраняет и восстанавливает модель.
- **Windows** (`src/core/ps-wrapper.ts`):
  - в PowerShell-обёртку добавлен параметр `-Model`;
  - при вызове формируется `opencode run --model "$Model" <промпт>`;
  - `run-<task>.cmd` передаёт `-Model "<model>"` (кавычки/переводы строк вычищаются).
- **Linux/macOS** (`src/core/wrappers/bash.ts`):
  - переменная `MODEL`;
  - функция `run_opencode()` вызывает `opencode run --model "$MODEL" "$PROMPT"`,
    если модель задана, иначе — обычный `opencode run "$PROMPT"`.
- Пустая модель = модель OpenCode по умолчанию (флаг не передаётся).
- `CreateTaskOptions.model` и `RegistryEntry.model` — модель хранится и в реестре
  POSIX-бэкенда.

## 2. Приоритеты

- `TaskDefinition.priority?: number` — целое 0..10 (10 — максимум).
  Нормализация: `normalizePriority()` в `src/task-transfer.ts`.
- Значение по умолчанию — 5 («Обычный»).
- Соответствие в GUI: Низкий = 2, Обычный = 5, Высокий = 8, Критический = 10.
- Сортировка по убыванию при выборе задач к запуску:
  - `src/index.ts`, catch-up пропущенных запусков — сначала задачи с большим priority;
  - `src/core/record-history.ts`, `selectDependentsToTrigger()` — DAG-зависимости
    возвращаются отсортированными по приоритету.
- Приоритет также сохраняется в `CreateTaskOptions.priority` / `RegistryEntry.priority`.

## 3. GUI

- Поля формы:
  - **Модель LLM** — текстовое поле с datalist популярных моделей,
    placeholder `по умолчанию (как в OpenCode)`;
  - **Приоритет** — выпадающий список Низкий / Обычный / Высокий / Критический
    (поддерживается и «Другой (N)», если в задаче сохранено нестандартное значение).
- Карточка задачи:
  - `🧠 <model>` — если модель задана;
  - `🚀 <приоритет>` — если приоритет отличается от «Обычного».
- Модель и приоритет входят в пользовательские шаблоны (`templates.ts`).
- История: в каждой строке показывается `🧠 <model>`, если модель известна.

## 4. Веб-дашборд

- В таблицу добавлены колонки **«Модель»** и **«Приоритет»**
  (`🧠 ...` / `🚀 ...`, для «Обычного» — прочерк).
- Добавлен блок **«📜 История выполнений»** — последние 10 запусков:
  время, задача, статус, длительность, модель и текст ошибки.
- `GET /api/history` уже существовал; страница теперь его использует.
- История хранит `model` (см. ниже), старые записи без модели отображаются без значка.

## 5. История выполнений

- `HistoryRecord.model?: string` (`src/history.ts`, `src/core/record-history.ts`, RPC-схема).
- Обёртки передают модель 8-м аргументом в `record-history.js`:
  `node record-history.js <task> <status> <startedAt> <durationMs> <error> <tokens> <cost> <model>`.
- `-` или пустая строка = модель не задана, поле в историю не пишется.
- Старые записи history.json остаются совместимыми (поле опционально).

## 6. RPC

Добавлены поля `model` и `priority` в:
`TaskItem` (get_tasks), `CreateTaskInput`, `UpdateTaskInput`,
`HistoryRecord` (get_history), `TemplateItem`, `SaveTemplateInput`.

## 7. Проверки

- `npm run build` — без ошибок.
- `npm run build:gui` — без ошибок (`gui-experimental.cjs`, ~52 kB).
- Сгенерированная bash-обёртка содержит `MODEL`, `run_opencode()` и передаёт
  модель в recorder.
- Сгенерированный `.cmd` содержит `-Model "openai/gpt-4o"`.
- Импорт задачи с `model` и `priority` сохраняет оба поля.
- DAG-сортировка: задачи с priority 9 и 5 запускаются в порядке `[B, A, C]`.
- `record-history.js` с 8-м аргументом пишет `model` в history.json.
- Живой дашборд: страница содержит колонки «Модель»/«Приоритет» и блок истории;
  `/api/tasks` отдаёт `model` и `priority`.

## 8. Ограничения

- Фактическое исполнение `opencode run --model ...` проверено только по
  сгенерированным командам; на реальных Linux/macOS нужен прогон с установленным OpenCode.
- Приоритет влияет на порядок запуска готовых задач (catch-up и DAG), но не
  переупорядочивает уже работающие процессы и не заменяет `maxConcurrent`.
- Модель не проверяется на существование — ошибку вернёт сам OpenCode при запуске.
